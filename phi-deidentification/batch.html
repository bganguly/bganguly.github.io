Batch Processing — Live Pipeline

50 clinical records generated on the fly in your browser using randomised names, SSNs, MRNs, dates, addresses, and phone numbers — no pre-existing files. Each record is submitted live to the PHI pipeline on Cloud Run: spaCy tier-1 NER handles ~90%, Claude Haiku 4.5 covers ambiguous fallbacks. Watch completions stream back in real time.

How it works
  1. Records generated in your browser — 50 clinical notes built from randomised Faker values (name, SSN, MRN, DOB, address, phone). No files. No uploads.
  2. POST /ingest — all 50 sent as one batch. The API writes a Job + 50 Record rows to PostgreSQL, enqueues one Celery task per record onto Redis, and returns a job_id immediately.
  3. 3 Celery workers process in parallel — each reads its Record from PostgreSQL and runs spaCy biomedical NER + regex (SSN, MRN, PHONE, EMAIL).
  4. Claude fallback (tier-2) — only triggered when spaCy finds nothing but the text contains PHI-indicator words. Mean entity confidence ≥ 0.85 → spaCy result used as-is. Below threshold → Claude Haiku 4.5 extracts entities as structured JSON and results are merged.
  5. Synthetic substitution — each detected span is replaced with a Faker value matched to its type. Entities are processed right-to-left so replacements don't shift earlier character offsets.
  6. Two writes, one commit — deidentified_text saved to the Record; one audit-log row per entity with a SHA-256 hash of the original value. Raw PHI is never stored.
  7. Results stream back — the browser polls GET /records/{job_id} once per second until all 50 complete.
